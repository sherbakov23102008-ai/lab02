## Цель работы
Посмотреть, как C# превращается в IL, изучить DLL, сравнить Debug и Release и измерить время выполнения метода.



В программе используется n = 100_000_000, чтобы измерения обычно занимали меньше времени. Для честного сравнения оставьте одно и то же значение в Debug и Release.

## Наблюдения по ILSpy
- В .NET-сборке хранятся IL-инструкции и метаданные, а не только исходный C#.
- Декомпилированный C# похож на исходный, но может отличаться оформлением и структурой.
- В методе `Add` на уровне IL можно увидеть загрузку аргументов (`ldarg`), сложение (`add`) и возврат (`ret`).
- Цикл в `SumTo` представлен в IL сравнением и переходами, а не отдельной инструкцией `for`.
- В Debug обычно больше промежуточных инструкций, а Release применяет оптимизации. Точные отличия и число инструкций нужно проверить в ILSpy на своей сборке.

## Ответы на контрольные вопросы

1. **Что такое IL и зачем он нужен?**  
   IL — промежуточный язык .NET. Он отделяет исходный код от конкретного процессора, а JIT преобразует IL в машинные инструкции при выполнении.

2. **Почему DLL можно декомпилировать?**  
   В .NET-сборке есть IL-инструкции и метаданные, по которым можно восстановить код, похожий на исходный.

3. **Какие отличия Debug и Release видны в IL?**  
   Обычно в Debug больше промежуточных инструкций и локальных переменных, а в Release часть операций оптимизируется. Точные отличия нужно записать после сравнения в ILSpy.

4. **Почему Release обычно быстрее Debug?**  
   При сборке Release применяются оптимизации, уменьшающие лишние операции. Но ускорение не гарантировано.

5. **Почему строковый пароль в DLL не защищён?**  
   Строки могут храниться в читаемом виде и извлекаться декомпилятором или HEX-редактором. Секреты нужно хранить отдельно в защищённом хранилище.
